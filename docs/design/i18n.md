# Internationalization

Clients translate their own interface. They can do nothing with a sentence received from the
server in one fixed language: neither translate it nor recognize it. There are three ways out:

| Approach | Drawback |
|---|---|
| The server translates everything from `Accept-Language` | It needs every language's catalog; a client cannot add a language without updating the server |
| The server only returns codes | A simple client has nothing to display; each new code forces every client to update |
| Both: a code with its parameters **and** a fallback text | Neither. This is what Laterna does |

## A server text is a key and parameters

The server composes no sentence in code. Any text meant for a person is a `domain.Text`: a
**stable key**, **named parameters**, sometimes a **list** of other texts. Whoever displays it
translates it:

- the client, with its own catalogs, in any language it wants;
- the server itself (`internal/i18n`), which always writes the fallback text.

The fallback is written in the language of the request if the server has its catalog (**English**
and **French**), in English otherwise. A client can therefore always display it as is.

## Errors

Every expected error carries a **code**: `library.not_found`, `auth.username_too_long`.

- Format: the domain, a dot, the reason in `snake_case`.
- A published code never changes meaning.
- The Connect error keeps its family code (`NOT_FOUND`, `INVALID_ARGUMENT`…) and gets a
  `laterna.v1.ErrorDetail`: `code`, `params` (named parameters, `max` = `64`) and `causes`
  (texts, when the error has several reasons, as in `playback.unplayable` or `theme.rejected`).
- Its message is the fallback text.
- An unexpected error carries `server.internal`: it is logged and nothing is said about it.
- An error with no detail comes from the transport (message too large, invalid JSON).
- On routes outside Connect (images, streams, downloads), the code is in the `Laterna-Error`
  header and the body is the fallback text.

## Parameters

| Kind | Written as | Example |
|---|---|---|
| Name | `snake_case` | `retry_after_seconds` |
| Number | decimal | `max` = `64` |
| Duration | seconds, name ending in `_seconds` | `retry_after_seconds` = `900` |
| Size | bytes, name ending in `_bytes` | `max_bytes` = `8388608` |
| ID | canonical form | `item_id` |
| `reason` | a technical diagnostic, **in English** | the error from another server or a file |

## Twin text fields in the contract

One rule: **a field `x` written by the server has a twin `x_text`** (a `Text` message: key,
parameters, list, and the rendered text). The original field stays, written in the language of
the request, so a client that does not translate has nothing to change.

| Message | Field | Twin | Keys |
|---|---|---|---|
| `HomeRow` | `title` | `title_text` | `home.resume`, `home.latest`… |
| `ActivityEntry` | `summary` | `text` | `activity.login`… |
| `StartPlaybackResponse`, `Download` | `reasons` | `reason_texts` | `reason.video_unsupported`… |
| `Integration` | `error` | `error_text` | `error.integration.unreachable`… |
| `JellyfinUser` | `problem` | `problem_text` | `import.problem.…` |
| `PollOidcLoginResponse` | `message` | `message_text` | `oidc.…` |
| `WatchPartyResponse` | `ended` | `ended_text` | `party.ended.…` |

## Names given by the server

A season almost never has a title; an episode not always; an untagged track has neither artist
nor album; a volume not always a title.

- These names are **stored in English**, as files already write them: "Various Artists" is the
  compilation artist for MusicBrainz, "Episode 5" the title of an episode not yet named
  upstream. The name given by the server and the same name read from a file are one and the same.
- When displayed, the server recognizes them (`domain.SeasonName`, `EpisodeName`, `ArtistName`,
  `AlbumName`, `BookName`) and writes them in the language of the request.
- On the item itself, a twin says the name comes from the server: `Season.title_text`
  (`name.season`, `name.specials`), `Episode.title_text`, `Artist.name_text`
  (`name.unknown_artist`, `name.various_artists`), `Album.title_text`, `Book.title_text`,
  `Theme.name_text` for built-in themes.

## Language of a request

In order:

1. the `Accept-Language` header, if the server has one of the requested languages;
2. otherwise the profile's language (`Profile.language`);
3. otherwise the server's language (the `language` setting, "en" by default).

`Profile.language` is a free tag ("fr", "pt-BR"): the client may have a language the server
lacks, and the choice follows the profile from one device to the next. Each profile sets its own
(`ProfileService.SetLanguage`), even a restricted one. `GetServerInfo` announces the server's
language and the ones it can write.

## Catalogs

`internal/i18n/locales/en.json` and `fr.json` hold the same keys. English is the reference.

Templates use `{name}`, plus formats for what is not written the same everywhere:

| Format | Rendering |
|---|---|
| `{retry_after_seconds:duration}` | "15 min", "6 h", "3 d" |
| `{max_bytes:bytes}` | "8 MiB" |
| `{position_seconds:clock}` | "1:23:45" |
| `{value:onoff}` | "on" / "off" |
| `{list}` | the texts of the list, rendered then joined |

**No plurals**: messages are worded to do without ("added: 3"). The client has the number as a
parameter and can agree it as its language requires.

Logs, internal errors, the command line and metric help are always in English.

## Guard rails

Two tests make forgetting impossible:

- **sources** (`TestSourcesMatchCatalogs`): every `domain.NotFound("…")`, `domain.T("…")` in the
  code names a key of the catalog and gives it all the parameters its message expects; every key
  of the catalog is used somewhere;
- **catalogs** (`TestCatalogs`): the same keys and the same parameters in every language.

## For contributors and clients

- **Client**: for an error, translate `ErrorDetail.code` with `params`, or display the message.
  For a text, translate `key` with `params` and `list`, or display `text`. The server's two
  catalogs can be a starting point.
- **Adding a language to the server**: a `locales/<language>.json` file and a constant. The
  catalog test says what is missing.
- **Adding an error**: its code in the code, its message in both catalogs. The source test
  refuses one without the other.

Limits: a `reason` parameter stays in English; titles frozen in the play history keep the name
as it was when played.
